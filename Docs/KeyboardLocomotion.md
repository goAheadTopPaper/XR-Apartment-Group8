# 键盘走路与家具碰撞

## 问题与修复

2026-10-31 在 `SCN_Kitchen_Cooking` 复现：默认 FPS 模式按住 A，视点从 `(-3.15, 1.36, 1.12)` 穿过橱柜和外墙，最终到达约 `(-5.95, 0.97, 1.12)`。橱柜表面约在 X=-4.48m。以上坐标仅描述这个版本的测试路径，不用于厨房尺寸或通行结论。

碰撞体存在，角色层与环境层也允许碰撞。原因是 XRI 的通用模拟器把键盘平移写入模拟头显及控制器的追踪位置，角色胶囊随后跟随这个位置；这条路径没有经过 `CharacterController.Move`。对照时把相同位移交给原有 XRI 角色移动路径，胶囊会在橱柜前停住。

`KitchenInteractionSimulator` 继承 XRI 3.5 的 `XRInteractionSimulator`。默认 FPS 模式中，它只接管走路平移，把键盘轴和鼠标滚轮位移排入现有 `XRBodyTransformer`，由已配置的 `CharacterControllerBodyManipulator` 执行碰撞移动。旋转、点击交互、手柄与手部模式仍交给 XRI。没有改家具碰撞、玩家胶囊尺寸、移动速度、场景或光照。

项目自己的 `XR/InteractionSimulator/XR Interaction Simulator.prefab` 只替换模拟器脚本 GUID，原输入引用和其他字段保留。未修改 `Assets/Samples` 或 PackageCache。更新模拟器副本时须保留这个派生组件。

## 使用与边界

- Play 后点击 Game，默认 FPS 模式的 WASD 走路会被实心家具和墙阻拦，可以沿表面滑动、反向离开或通过实际开口。
- Y 显示 XRI 原有提示。单独操控手柄仍然只改变手柄姿态；专门的头部姿态编辑模式仍用于模拟追踪，不作为走路模式。
- 自动模拟器仍只在 Editor 创建。真实头显测试前仍须关闭自动模拟器；本修复不钳制真实追踪头部，也不代替 SAFE-01 的安全提示或 Quest Link 验收。
- 滚轮归一化沿用锁定的 Unity 2022 / XRI 3.5 规则：Mac 除以 20，Windows 除以 120。升级这些依赖时须一起核对该规则。

## 回归验证

`KeyboardSimulatorCollisionTests` 使用实际烹饪场景、Rig、环境碰撞体和模拟器 Prefab，通过模拟器输入读取器和渲染帧驱动，覆盖：

1. 持续向橱柜移动时停住，随后能反向离开；原实现会在此失败。
2. 能往返厨房门口，朝实体墙移动时被阻拦。
3. 斜向移动时沿柜面滑动；按移动后位置查询实际网格表面，不把圆角网格假定为绝对平面。
4. 视角旋转与单独调整控制器姿态仍可用，且不会被误判为走路。

最终 EditMode **145/145**、整批 PlayMode **56/56** 通过，包含上述 4 项、原有抓取、整屋重置和完整菜谱。本次菜谱通过不代表此前物理操作测试的间歇波动已被修复。控制台 0 error，617 个原有场景 / Prefab / 参数 / 工程 / XR 文件逐字节不变；模拟器 Prefab 单独核对，仅脚本引用改变。

测试日志与修复前后的直接证据位于忽略入库的 `Logs/KeyboardCollision/`。编辑器测试不代表 Windows Player 或头显体验已验收。
