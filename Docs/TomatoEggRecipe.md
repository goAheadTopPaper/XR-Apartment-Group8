# 西红柿鸡蛋交互流程

本功能是 `SCN_Kitchen_Cooking` 中的独立烹饪流程，用于用户新提出的厨房交互需求。正式评审的 Core、B1/B2、反馈和 CSV 契约保持独立，不把烹饪完成写成 Phase 2 评审任务完成。

## 打开和操作

Unity 菜单 `XR Apartment → Cooking → Open Cooking Kitchen`，进入 Play。起点在厨房小房间过道，面对备料台；蔬菜、水果和鸡蛋在右侧冰箱层板上，刀板、碗、锅铲、搅拌器、煎锅和燃气灶在厨房台面。沿用项目的移动、转向和传送；键鼠模拟帮助用 Y 查看。真实头显仍须在 Windows 上连接对应 OpenXR 运行时并关闭自动模拟器。

1. 选择冰箱把手开门，抓住番茄，从层板上提起并取出。关门时不能隔门选择食材。
2. 把番茄放到切菜板，抓刀向下切，先得到四片；每片再次切开，得到十六块。切片和小块沿用同一确认模型的几何、外表面与尺度。
3. 再打开冰箱取鸡蛋，拿起搅拌碗。把鸡蛋放在碗口附近向下磕，蛋壳打开，显示落入碗中的蛋液；碗上方按触发键也可以打蛋。
4. 用搅拌器尖端在蛋液中划动，直到蛋黄和蛋清混合。把碗放稳。
5. 选择燃气灶前方的黑色旋钮开火，出现蓝色火焰。拿起煎锅并平放在炉面。煎锅初始放在炉旁，系统不会自动摆锅或自动开火。
6. 拿起碗，在锅口上方倾斜，蛋液沿可见的重力轨迹流入锅中。水量 / 蛋液量按原有有限体积逻辑处理，不凭动画凭空增加。
7. 蛋液受热逐渐变色、凝固并出现有体积的熟蛋块；用锅铲在锅内划动、翻动。只有抓住锅铲后实际铲头位置的运动才计入翻炒，追踪虚影不计入。
8. 抓住装有番茄块的切菜板，移到锅上方倾斜；也可先把番茄块放到备料碗，再拿起倾倒。食材随容器移动，倾斜后释放到重力物理，真正进入锅口后才计入锅中。
9. 继续加热，用锅铲把番茄和鸡蛋翻拌。足量番茄和鸡蛋都熟、且发生了实际翻炒后，显示完成。关闭炉灶；继续加热会变焦。
10. 选择 RESET，恢复完整番茄、鸡蛋、刀具、容器和锅中内容，食材回到冰箱，冰箱门关闭，炉灶关闭。

桌面和冰箱附近都有当前步骤提示。已完成的准备动作会保留记录，但单靠等待、空锅挥动、冷锅搅拌、完整番茄或仍握在手里的番茄都不能完成菜谱。

## 模型与实现边界

- 完整番茄来自上轮实际 Comfy Cloud Pixal3D 单图结果。`tomato/v002/prepared_recipe/` 从 v001 派生两级交互切分与碰撞，每一级封闭、分块体积误差不超过 2%。可见的切片 / 小块随后换为新生成的带籽、果肉模型，适配到既有代理范围，保留切分事件和食材份量；可见体积不反推食材质量。
- 熟蛋块已换成 Comfy Cloud 实际生成的自然褶皱网格，具有近景 / 远景两档和独立 PBR。番茄切面和熟蛋生成任务、来源及替换方式见 [FoodVisualUpgrade.md](FoodVisualUpgrade.md)，当前加工结果在 `ArtSource/KitchenAssets/Recipe/v002_food_visuals/`。
- 首版冰箱、门板、锅铲和切菜板由本地 Blender 制作，来源 `Recipe/v001/` 作为历史保留。当前冰箱门、主要厨具和灶具使用实际生成并整理过的模型；箱体大平面、内胆和水槽 / 龙头由本地精修。来源和厨房内布置见 [KitchenRoomAndCookware.md](KitchenRoomAndCookware.md)。门继续使用固定铰链、运动学缓动和保守旋转扫掠。
- 可交互部件均为 Prefab。锅铲、切菜板、碗、锅与食材继续使用 `KitchenGrabAuthoring` 的整物防穿模；没有通过放松房间碰撞来实现翻炒。
- 为让有限数量的食材可稳定翻炒，进入锅中的已释放番茄由 `KitchenPanContents` 接管，以池化模型呈现翻动。它们保留实际食材份量和受热状态；这不是任意食物刚体求解或真实热传导。
- 切菜仍为准备好的两级变体，不支持任意切面。熟蛋块是凝固和翻炒的游戏表现，未实现蛋白质、油、水的多相流体。当前完成结果在锅中；未增加进食、评分、调味或营养系统。

## 维护入口

| 文件 | 职责 |
| --- | --- |
| `Tools/ComfyCloud/blender_recipe_assets.py` | 派生切片 / 小块，制作冰箱、锅铲、切菜板与熟蛋模型，输出 FBX / GLB 和来源记录 |
| `Editor/KitchenRecipeAuthoring.cs` | 烹饪流程专用 Prefab、食材身份 / 份量、冰箱摆放、锅中模型与提示接线 |
| `Simulation/TomatoEggRecipe.cs` | 与 Unity 无关的动作证据、完成条件和烧焦 / 重置状态 |
| `Runtime/Cooking/KitchenRecipeController.cs` | 根据实际抓取、物品状态、倒入、热源和锅铲动作推进提示 |
| `KitchenStoredIngredient` / `KitchenFridge` | 关门选择过滤、实际取出、门体和灯 |
| `KitchenPrepTray` | 休息状态保留食材物理；拿起承载，倾斜 / 放下释放，不绕过容器防穿模 |
| `KitchenPanContents` / `KitchenSpatula` | 锅口接收、份量、熟蛋模型和实际翻炒 |

配置为 `SET_TomatoEggCooking`。菜谱样例保留 12 秒受热变熟，烧焦阈值设为 90 秒，给 VR 拿放、倒入和翻炒留出操作时间；上轮独立资产测试仍使用原来的 12 / 32 秒配置。尺寸和位置登记为 `ASM_KitchenParameters` 的 `cooking_*` 原型假设，不能用于客户空间结论。

切菜板与备料碗上的小块只在拿起容器时临时承载，倾斜后恢复刚体；放在桌上时仍可逐块抓取。刀需要实际刀刃接触和向下运动，抬刀后才能触发下一刀，避免一次接触直接切成全部小块。切分、倾倒释放和重置均同步 XRI 的目标姿态，避免其延迟更新把物品传回旧位置。抓取配置只收集同一刚体的实体碰撞体，查询用扫掠代理继续禁用。

## 验证

2026-10-28 在 Unity 2022.3.62f3 macOS 编辑器中，全项目 EditMode **145/145**、PlayMode **47/47** 通过，其中新增菜谱场景检查 **5/5**。覆盖关闭的冰箱不可选择、开门取物、桌面及冰箱支撑、两级实际刀刃切分、磕蛋 / 混合 / 有限体积倾倒、锅位与热源、锅铲翻炒、重力倒入番茄、完成 / 变焦 / 重置，以及门体受阻后继续开启。

完整场景测试驱动真实 XRI 抓取、选择和激活，并经过实际碰撞、重力和容器接收；没有直接设置菜谱完成状态。本次全量回归中，50.000004mL 蛋液进入锅中，番茄切为 16 块，实际落入锅内 14 块、110.22831g；达到 90g 最低份量，掉在锅外的部分未计入。冷锅挥铲、整颗番茄、切片或仍被手持的番茄均不能代替有效操作。

完成状态下采样 70 个编辑器帧，`XR Apartment.Cooking Presentation` 的局部 CPU 用时均值约 **0.01105ms**、最大 **0.01254ms**。这只测量锅中模型呈现，不是整个场景帧耗时，也不代表 VR 帧率。此 Mac 无活动 OpenXR 运行时，测试使用驱动的交互器；Windows Player、Quest Link 手感和帧率尚未验证。

上述为完整菜谱首版的实测记录。模型精修后的当前结果见 `ArtSource/KitchenAssets/Validation/FoodVisuals/validation.json` 和同目录 Unity 截图，完整日志位于 `Logs/FoodVisualUpgrade/`。首版记录与图片保留在 `ArtSource/KitchenAssets/Validation/Recipe/`，避免把旧图当成新模型证据。原评审场景及光照的 19 个受保护文件 SHA256 校验一致，工程 / 包 / XR 输入配置和 Build Settings 无改动。
