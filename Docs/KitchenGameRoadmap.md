# VR 厨房的交付顺序

玩家从城市窗景厨房进入。正式评审、布局实验和做饭共享抓取、开门、切配与移动手感，只有正式评审会生成方案比较证据。

## 当前可玩的版本

- 进入城市厨房会先显示 **厨房引导**。选择站姿或坐姿并校准眼高，练习瞬移和抓放厨具，再按台面提示做西红柿炒蛋。成菜并关火后，引导会出现冰箱预览。通过 **布局实验** 在同一摆位试开两款，查看实际开门角度。
- 在引导的反馈阶段取出 **反馈便利贴**，靠近冰箱门、台面、水槽或厨具等物品后松手。确认物品名称，输入反馈并保存，再选择 **开始自由活动**。自由活动时可以继续添加便利贴。每次保存向 `Application.persistentDataPath/KitchenFeedback/feedback.txt` 追加物品名称和 ID、布局与冰箱尺寸、时间和反馈原文。已保存的便利贴在本次游玩中跟随物品。
- 长按 Quest 左手 **Menu** 或键盘 **F8** 约半秒，暂停菜单会定位在玩家当时的视线前方。菜单打开时暂停料理、流水、物理和环境音，手柄射线可继续操作菜单。选择 **继续游戏** 或在暂停主页再次长按恢复。**设置**里可以切换 **简体中文 / English**。
- 握住冰箱把手后沿门扇弧线拉动，松手时门停在实际位置。关门时握住把手向回推。做饭、布局实验以及正式评审的 F2 共用这一操作，门扇受阻时由原有扫掠检测限制转角。
- 冰箱预览与自由活动时，也可按右手 **B** 或键盘 **F9** 打开布局实验。A 将冰箱放在水槽对面的墙边，门朝向水槽。原冰箱位恢复原有柜体。B 将冰箱从右墙向水槽前移 16 厘米，C 在 A 的开门路径旁加一座窄柜。每种摆位都能单独选择 72 厘米全尺寸款或 61.2 厘米紧凑款。开门后重新呼出菜单，可以在同一布局内并排看两款的实测门角。切换后道具归位，食材回到当前冰箱的搁板，菜谱重新开始。目标区域有障碍时保留当前布局与烹饪状态。
- 同一个菜单可独立选择 **Warm Ivory** 暖白、**Sage** 鼠尾草绿或 **Graphite** 石墨灰。配色可在做饭中途切换，随后继续当前料理或比较已测门角。选 **Warm Ivory** 恢复原配色。
- 冰箱有 11 件可拿取食材。在台面按 **RECIPE** 切换西红柿炒蛋和洋葱炒牛肉，切换会归位道具和食材。炒牛肉要从冰箱取出两种食材，切配后放手入锅，点火煎熟并用锅铲翻炒。关火后拿起锅，将倾斜的锅沿对准盘面。装盘完成后可端起盘子。
- 冰箱卡显示还要取的食材，开门受阻时说明下一步。台面卡显示菜谱步骤和当前操作对应的进度，例如已切片数、蛋液搅拌比例和锅内份量。两张卡都使用场景内的世界空间文字。 [Unity 世界空间 UI](https://docs.unity3d.com/2022.3/Documentation/Manual/HOWTO-UIWorldSpace.html)
- 自由活动时，在暂停菜单的 **设置** 中选择 **Start Design Review** 进入正式评审。固定柜板挡住 F2 时，系统标出实际障碍，并把角度和对应登记项纳入本地证据。评审场景请求 Floor 跟踪模式，安全提示单独读取运行时提供的物理活动区。进入和清除阈值暂设为 25 和 35 厘米，待 Quest Link 校准。[Unity XRInputSubsystem](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/XR.XRInputSubsystem.html) · [OpenXR Stage reference space](https://registry.khronos.org/OpenXR/specs/1.1/man/html/XR_REFERENCE_SPACE_TYPE_STAGE.html)
- 完成 Orientation 后选 **Start Explore**，用预览栏自由切换 B1 和 B2。B1 提示观察冰箱突出时的通行与开门，B2 提示观察同一冰箱与齐平柜体之间的开门净空。选中会话顺序里的下一方案时，**Challenge** 才可用。
- 正式任务卡可用 **Compact** 缩小，再用 **Expand** 展开。整理步骤把番茄或洋葱放到指定冷藏层并松手后，可直接在任一任务卡确认。走近冰箱或台面时，任务文字和按钮仍显示在前景。
- 红色边界警示出现后，等待有效采样确认已离开警示范围才消失。暂停、最终提交或安全退出时，当前检查点会将警示的触发时间与方案保存到匿名记录。离线对照页在会话概览显示边界警示，在各方案卡片显示设计冲突。
- 两个方案的反馈完成后，在最终比较页选择偏好，再点 **Write in VR**。用手柄射线选择英文字母、数字和标点，**Done** 返回比较，最后点 **Confirm comparison**。电脑键盘可以直接编辑同一个输入框。暂停、打开恢复菜单或收到实体边界提示会收起键盘并保留文字。键盘使用现有世界空间 UI 射线路径。[Unity XRI 世界空间 UI](https://docs.unity3d.com/Packages/com.unity.xr.interaction.toolkit@3.5/manual/ui-setup.html)
- 评审进行中，按右手 **B** 或键盘 **Esc** 打开恢复菜单。实际坐稳或站稳后选 **Calibrate seated** 或 **Calibrate standing**。手上有物品时先放下。Setup 调整过的眼高按姿态保留，重新校准或恢复评审时沿用同一轮任务与草稿。虚拟眼高用独立偏移层，头显与双手一起移动，瞬移地面参考和实体边界坐标照常工作。[Unity XR Origin](https://docs.unity.cn/Packages/com.unity.xr.core-utils@2.5/manual/xr-origin-reference.html)
- 取低层食材时，先开冰箱门，再用手柄射线瞄准并按住握持键。向后拨同侧摇杆拉出，向前拨把食材送回层板，然后松手。关门和离开步骤中使用 **Restore step**，会把三件任务食材分开摆回有实体支撑的层板。[Unity XRI Near-Far Interactor](https://docs.unity3d.com/Packages/com.unity.xr.interaction.toolkit@3.5/manual/near-far-interactor.html)

## Mac 本机验证

使用 Unity 2022.3.62f3。通过 **XR Apartment > Open Main Kitchen** 打开城市厨房，或通过 **XR Apartment > Open Kitchen Review Scene** 直接打开正式评审。点 **Play** 后让 Game 窗口获取焦点，用 **WASD** 和鼠标移动，按 **Y** 查看模拟器快捷键。可先在 Setup 调整眼高，再在评审和暂停状态用恢复菜单切换姿态。两种姿态的真机可达性和舒适度待现场验证。

## 布局如何保持可复现

三个预设使用同一房间和台面。两种冰箱复用同一套网格和贴图，紧凑款按 85% 等比缩放，门、拉手和扫掠体一起缩小。切换先验证当前所选尺寸的闭门空间，再登记当前冰箱的门体和碰撞，归位原尺寸食材，并重新连接菜谱的取物事件。厨房尺度登记在原型参数表，以实测开启角和通行结果验收。

三套配色覆盖厨房台面、窄柜柜身和两种冰箱的外壳与门板。近远两档冰箱共用同一套颜色。场景内指定渲染器通过属性块应用色值，复用现有材质、网格、贴图和烘焙光照。每次进入城市厨房从 Warm Ivory 开始。 [Unity Renderer.SetPropertyBlock](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Renderer.SetPropertyBlock.html)

## 食材和制作

切西红柿时先把食材放在砧板上，握刀持续向下压。第一、第二刀各分出一片，剩余部分保持完整形状并露出新的切面。第三刀分开最后两片。每刀之间抬起刀刃，之后可把切片继续切丁。台面卡显示已完成刀数。外皮、切面纹理和切丁沿用已有 Comfy Cloud Pixal3D 素材，Blender 从完整番茄派生四片、两级余料及对应余料碰撞代理。

先在现有冰箱里增加可抓取的水果、蔬菜和蛋，填补肉类的模型缺口，再按菜谱需要制作预切件。已有资产优先复用，同种食材的多个实例共用网格和贴图。冰箱闭合时沿用现有的选择过滤，取出与复位继续走同一套交互。用现有番茄切片和熟蛋池作为参考，控制切分后的刚体数量、共用碰撞体和烹饪表现。

牛肉使用 `KitchenBeefAuthoring` 制作的整块和四条预切件，总重是游戏内的 150 克，复用抓取、刀、备料容器和锅铲。把肉条降到锅口内并放手，开火后等待变色，再用锅铲翻动。炉灶对锅里的固体食材提供声音和蒸汽反馈。牛肉的生熟焦与番茄炒蛋进度分别统计。整块和切条共用两种材质，首轮原型的贴图预算为零。

洋葱沿用原有整颗模型，切开后四块共用一个轻量切块网格，游戏内总重 80 克。洋葱炒牛肉分别检查取出、切配、入锅份量和生熟，并要求两种食材在实际受热的锅内接受锅铲翻动。装盘会转移已煎熟的牛肉和洋葱，装盘结果随后跟着盘子移动。复位保留当前菜谱选择。

平放的番茄薄片可能比实体刀具保守扫掠的停止点更低。刀刃触发区沿局部 Z 轴从 0.08 m 调到 0.12 m，每侧补足 20 mm。实体碰撞体、扫掠和下切速度门槛沿用原配置。切分仍须由被抓住的实际刀具触及食材，头显下的接触感待现场检查。

需要新外观时可用混元 3D 或 ComfyUI。先用一件样品核对轮廓、握持、碰撞和贴图，然后再扩同类资产。临时工作流、重复导出和未采用的预览从本轮工作目录清理。入库只保留采用的游戏资产、可复用流程和必要的来源、许可、参数。

## 每轮验收

厨房和餐区加了近地板的烘焙探针。城市厨房的餐桌由吊灯下沿的烘焙聚光照明，备料台和灶台由正上方的烘焙面光覆盖。贴地的可抓取物品从地板上方 14 厘米采样间接光，光照取样点不影响物品的姿态或碰撞。地板下方的承托碰撞与外缘挡板提供虚拟场景保护，虚拟角色落出有效区域时回到最近的有效地板位置。

东侧过道增加了烘焙面光和从近地面到站姿视点的探针覆盖。双手共用玩家视点作为探针取样点，在过道里转身或把手伸近墙面时仍能获得稳定的间接光。烹饪与正式评审场景都已重烘焙并复测探针，城市厨房留有同机位的前后对照。

抓取、落地、开关门、切菜、触板、炉灶、菜单和脚步使用新合成的短音效。门扇受阻和切入时由实际交互触发手柄脉冲。参考了 Valve 在 Alyx 开发访谈中对手部操作及声音反馈的设计。 [Valve 的 Alyx 开发分享](https://store.steampowered.com/news/posts/?appids=546560&enddate=1588698455)

每轮从真实场景入口做专项操作，再跑 EditMode 和 PlayMode 回归。能影响玩家体验的变化，用同一路径对比菜单可读性、开门和抓取反馈、切换时的遮挡与重置、灶台操作和装盘。记录新增网格、贴图、运行时刚体及性能采样。最后在目标设备测交互稳定性、帧时间和眩晕相关体验，编辑器 CPU 数据单列。

首轮 EditMode 151/151、PlayMode 65/65，专项复测 5/5。窄柜版门扇在约 20° 受阻，移开窄柜后同一扇门开到 105°。三套布局都通过关门状态下的入口、冰箱与台面通路检测。

Windows64 构建成功，Unity 报告约 544 MiB。按构建报告的未压缩用户资源统计，纹理占 96.2%，包括全景天空、两套烘焙光照和大尺寸法线及金属度贴图。后续优先逐组核对可降采样的小件纹理，在头显近距离比较画面后再定导入规格。Windows Player 的实际运行和 Quest Link 验收仍待完成。

第二轮 EditMode 151/151、PlayMode 67/67，最终专项 5/5。两种冰箱都通过三套布局的通路检测。在同一窄柜旁，全尺寸款测得约 20°，紧凑款测得约 32°，两者分别落在取物门槛两侧。紧凑款实测能抓取番茄并推进菜谱。牛肉实测能切出四条、经锅口入锅、在实际热区煎熟、用锅铲翻动、烧焦和复位。牛肉整块 116 三角形，四条共 226 三角形。第二轮 Windows64 构建成功，比首轮增加约 59 KiB。

第三轮 EditMode 151/151、PlayMode 67/67，Windows64 构建成功，比第二轮增加 31.2 KiB。洋葱四块共用一个 92 三角形切块网格。洋葱炒牛肉的场景测试在实际炉面预置锅位，验证 150 克牛肉与 80 克洋葱的取料、刀切、入锅、受热、翻炒、关火、烧焦保护、倾锅装盘、端盘和复位。西红柿炒蛋的回归通过实际 XRI 抓取摆锅。正式评审测试读回最终 CSV，核对 B1、B2 反馈、偏好和取舍说明。冲突测试把已登记的 B2 柜板临时移入门扇路径，用实际扫掠确认警示和角度写入，再恢复作者布置。当前默认配置的这次测试中，两套门均能开足角度。

## 静态前测

打开 [离线前测](Evaluation/StaticBaseline.html)。B1/B2 取自 `SCN_Kitchen_Review` 的实际运行时绑定，同一台相机和光照下拍摄，均为闭门状态。两张图移除了任务区域标记，场景和相机设置一致。图像版本为 `mzh-1f501b3-kitchen-f2-hunyuan-v2`。后续如果变更评审模型，重新拍摄两张图并更新表单的模型版本。

1. 在同一台电脑先保存前测 JSON。参与者完成初始理解、各方案的预期问题和初始偏好，再进入 XR。
2. 主持人记录体验前已有的匿名会话 ID。体验后，从 `sessions.csv` 找到本次新增且已完成的行。Mac 编辑器的路径为 `~/Library/Application Support/DefaultCompany/XR-Apartment-Group8/ReviewRecords/sessions.csv`，Windows Player 的路径为 `%USERPROFILE%/AppData/LocalLow/DefaultCompany/XR-Apartment-Group8/ReviewRecords/sessions.csv`。
3. 回到前测页面，载入原前测 JSON 和游戏生成的 CSV，填写本次新增的 `session_id`，选择 **核对并查看对照**。页面核对完成状态、方案顺序、时间和模型版本，分别显示 B1/B2 的前测预期、参与者反馈和系统实测。门扇冲突显示受阻角度、发生时间、障碍 ID 和登记参数。
4. 记录 XR 补充、修正或可能误导的判断，然后下载单场关联 JSON。文件保留原始前测和本次会话详情。归档前测原件、关联 JSON 和该次评审的 CSV。页面在本地运行，参与者无需填写姓名或账号。
